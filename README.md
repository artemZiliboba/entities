## 📖 О проекте

**Entities** — это одновременно энциклопедия для чтения и открытый набор структурированных данных.

Каждое произведение хранится отдельно и описывает только те магические сущности, которые подтверждаются выбранным первичным или авторитетным источником. Для фольклорных текстов с несколькими версиями фиксируется конкретный вариант: детали разных редакций не смешиваются.

Сейчас каталог содержит **113 произведений** из разных традиций и литературных корпусов. Веб-интерфейс собирает их в удобную энциклопедию с поиском, навигацией и светлой/тёмной темой.

## 🧭 Что считается сущностью

В данных используются девять типов:

| Тип | Что описывает |
| --- | --- |
| 🪄 `artifact` | магический предмет |
| 🧙 `character` | магический или сверхъестественный персонаж |
| 👹 `creature` | сверхъестественное существо |
| 🏰 `location` | магическая или иномирная локация |
| 🧪 `substance` | магическое вещество, напиток или пища |
| 🌿 `plant` | магическое растение |
| 🐉 `animal` | магическое животное |
| ✨ `spell` | заклинание, формула или самостоятельное магическое действие |
| 🌌 `phenomenon` | самостоятельное магическое явление |

Главный принцип — **не превращать любой необычный элемент сказки в отдельную сущность**. Например, предмет, созданный магией, не обязательно считается магическим сам по себе, если после создания ведёт себя как обычная вещь.

## 🗂️ Как устроен репозиторий

```text
.
├── data/
│   ├── processed-works.yaml       # реестр обработанных произведений
│   └── works/
│       └── <tradition>/
│           └── <work-id>.yaml     # произведение и его сущности
├── schema/
│   └── work.schema.json           # JSON Schema для YAML-записей
├── examples/
│   └── catalog.md                 # демонстрационный каталог
├── index.html                     # оболочка GitHub Pages
├── app.js                         # загрузка данных и интерфейс
├── styles.css                     # стили сайта
├── theme.js                       # светлая/тёмная тема
└── .github/workflows/pages.yml    # публикация GitHub Pages
```

### Источник истины

1. **`data/works/**/*.yaml`** — сами записи произведений и сущностей.
2. **`data/processed-works.yaml`** — центральный реестр файлов, которые загружает сайт; при добавлении произведения он обновляется в том же PR.
3. **`schema/work.schema.json`** — допустимая структура записи, типы произведений и сущностей.

## 🧩 Живой пример

Ниже сокращённый фрагмент реальной записи [«Василиса Прекрасная»](data/works/russian-folklore/vasilisa-the-beautiful.yaml):

```yaml
id: vasilisa-the-beautiful
title: "Василиса Прекрасная"
kind: folktale
tradition:
  - russian-folklore

source:
  title: "Народные русские сказки (Афанасьев) — Василиса Прекрасная, № 104"
  url: "https://ru.wikisource.org/wiki/Народные_русские_сказки_(Афанасьев)/Василиса_Прекрасная"

entities:
  - id: mothers-magic-doll
    name: "Материнская куколка"
    type: artifact
    description: >
      Кукла, оставленная Василисе матерью вместе с благословением.
      После угощения она разговаривает с хозяйкой, помогает ей
      и выполняет трудные задания.
    tags:
      - magic-doll
      - helper
      - talking-artifact
```

Полная запись содержит источник, сведения о конкретной редакции и все подтверждённые сущности произведения.

## ➕ Как добавить произведение

1. Убедитесь, что произведения ещё нет в [реестре](data/processed-works.yaml) и в `data/works/`.
2. Выберите **одну конкретную редакцию или вариант** и надёжный первичный/авторитетный источник.
3. Прочитайте текст целиком и добавьте все самостоятельно значимые магические сущности — без искусственного лимита на их количество.
4. Создайте `data/works/<tradition>/<work-id>.yaml` по [JSON Schema](schema/work.schema.json).
5. Используйте устойчивые английские `id` в `kebab-case`.
6. Обновите `data/processed-works.yaml`: счётчик, SHA базы и путь новой записи.
7. В описаниях пересказывайте источник своими словами; не копируйте большие фрагменты текста.
8. Отправьте изменения отдельным pull request.

## 🌐 GitHub Pages

Сайт — статическое приложение без отдельного backend. После изменений в `master` workflow [`pages.yml`](.github/workflows/pages.yml) публикует репозиторий через **GitHub Pages**.

[![Open Encyclopedia](https://img.shields.io/badge/OPEN-ENCYCLOPEDIA-6f42c1?style=for-the-badge&logo=github)](https://artemziliboba.github.io/entities/)

Интерфейс загружает реестр произведений, читает перечисленные YAML-файлы и строит каталог в браузере. Переключатель темы учитывает системную тему и сохраняет ручной выбор локально.

## 🤝 Участие в проекте

Новые произведения, исправления источников и уточнения сущностей приветствуются через **Pull Requests**. Для вопросов, ошибок и предложений можно использовать [GitHub Issues](https://github.com/artemZiliboba/entities/issues).

При добавлении фольклора особенно важно указывать точную редакцию: одинаковое название нередко скрывает несколько существенно различающихся вариантов.
